# Hardhat package

`DmrvRegistry`, `CreditMarket`, `HydroVmr0017Module`, the `ResilientHbarUsdFeed` oracle aggregator, the HTS helper library, deploy scripts and tests.
The root [README](../../README.md) explains the system and the methodology; this file covers working inside the
package. Run commands from the repo root with the `hardhat:` prefix, or from this folder without it.

## Contracts

| File | Purpose |
| --- | --- |
| `contracts/DmrvRegistry.sol` | Plant registration, two-signature attestation, custody, retirement, all HTS calls |
| `contracts/CreditMarket.sol` | USD listings settled by swapping the oracle HBAR amount through SaucerSwap |
| `contracts/modules/HydroVmr0017Module.sol` | On-chain ER = BE − PE − LE for VMR0017 / CDM hydro |
| `contracts/ResilientHbarUsdFeed.sol` | Chainlink HBAR/USD with a Supra fallback behind `AggregatorV3Interface`; refuses to price when fresh sources disagree |
| `contracts/legacy/HydroCreditRegistry.sol` | Phase-0 registry, compiled and tested so live evidence still reproduces |
| `contracts/lib/HederaTokenLib.sol` | Create / mint / burn / transfer through the HTS system contract at `0x167`, reverting on non-`SUCCESS` codes |
| `contracts/interfaces/` | `IMethodology`, the subset of `IHederaTokenService` used, SaucerSwap, Chainlink's `AggregatorV3Interface`, Supra's `ISupraSValueFeed` |
| `contracts/mocks/` | `MockHederaTokenService` (installed at `0x167` on local chains and in tests), Chainlink, Supra and SaucerSwap mocks |

The contract is compiled with the IR pipeline (`viaIR`), which keeps the registry under the 24 KB code-size limit.

## Local chain

```bash
yarn chain:offline                  # plain Hardhat node, no internet needed
yarn chain                          # Hedera-forked node (HEDERA_FORKING=true) with real HTS emulation
yarn deploy --network localhost     # terminal 2
```

`deploy/00_deploy_dmrv_registry.ts` deploys oracle mocks on local networks and installs the HTS mock only when
nothing already lives at `0x167`, so it works with either node. `deploy/01_setup_dmrv_registry.ts` is idempotent:
it creates the HTS credit token and the NFT certificate collection, grants `VERIFIER_ROLE` to `VERIFIER_ADDRESS` if
set, sets the SaucerSwap pool guard, and registers the demo plants from `utils/demoPlants.ts` (integers generated by the methodology engine; a vitest
test fails if they drift). Every deploy regenerates `packages/nextjs/contracts/deployedContracts.ts`.

## Tests

```bash
yarn hardhat:test          # hermetic: HTS mock at 0x167, oracle mocks
yarn hardhat:test:fork     # same suite with the Hedera forking plugin (needs internet); mock-only checks skip
yarn hardhat:test:gas      # with gas report
```

`test/fixtures/quantificationVectors.ts` holds hand-checked emission-reduction vectors (greenfield with reservoir
emissions and diesel, retrofit across crediting years and past DATE_BaselineRetrofit). The contract suite and the
TypeScript engine's suite both assert them.

## Hedera testnet / mainnet

```bash
yarn hardhat:account:import           # or :generate; stored encrypted in packages/hardhat/.env
yarn deploy --network hederaTestnet   # or hederaMainnet
```

The deployer needs HBAR for gas (the registry deployment uses about 4.9 M gas) plus the two token-creation fees
(`CREDIT_TOKEN_CREATE_FEE_HBAR` and `CERTIFICATE_TOKEN_CREATE_FEE_HBAR`, default 20 each). Use an **ECDSA** account so
its EVM address can also act as the verifier. Hashscan links are printed for each transaction.

Verify on Sourcify (Hashscan reads it):

```bash
yarn hardhat:verify --network hederaTestnet <DmrvRegistry address> <admin> <minCompletenessBps>
```

The constructor arguments for `DmrvRegistry` are the admin and the minimum data completeness in basis points, matching
`deploy/00_deploy_dmrv_registry.ts`. `CreditMarket` takes the admin, registry, feed, native units per HBAR, max price age, SaucerSwap factory and router.
